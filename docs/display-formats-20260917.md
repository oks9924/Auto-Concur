# Concur 사용자별 표시 서식 방어

## 설정

첫 화면의 `Concur 표시 서식`에서 날짜 순서와 금액 서식을 선택한다.
- 자동 판단: 같은 셀의 ISO/레이블 또는 같은 목록의 명확하고 일관된 날짜 증거만 사용한다.
- 년/월/일, 월/일/년, 일/월/년: 사용자가 실제 Concur 계정 표시를 확인하고 선택한다.
- `1,234.00`(기본) 또는 `1.234,00`: 소수점과 천 단위 구분자를 명시한다.

설정은 프로그램의 settings.json에 저장하며 Concur 계정의 설정이나 작업지 원본을 변경하지 않는다.
다른 계정으로 로그인할 때 다시 확인한다. 한국어 UI 또는 브라우저 언어만으로 날짜 순서를 추측하지 않는다.

## 읽기·입력·검증

4자리 연도의 YMD/MDY/DMY, 점·슬래시·하이픈, 한국어 년월일과 영어 월명을 해석한다.
`09/08/2026`처럼 모호한 날짜는 명시된 설정이나 화면 증거가 없으면 보류한다.
같은 셀의 ISO 날짜와 표시가 충돌해도 강제로 맞추지 않는다. 날짜 없는 값, 불가능한 날짜,
한 필드에 여러 날짜가 섞인 값은 임의로 보정하지 않는다.

금액은 KRW 정수만 지원한다. 전각 숫자·줄바꿈 없는 공백·유니코드 음수 기호를 정규화한다.
소수부가 0인 `17,000.00`, 명시한 쉼표 소수점의 `17.000,00`, 괄호 음수와 후행 음수를 지원한다.
숫자만 남겨서 비교하던 상세 금액 확인은 제거했다. `170.00`을 `17000`으로 읽거나 음수를
양수와 같게 판단하지 않는다. 영수증 요약에서도 전체 숫자 토큰을 검사하여 `17 000`을
17로 잘라 읽지 않는다. 빈 객실 요금은 0원으로 간주하지 않는다.
외화·소수 원 단위·잘못된 구분자·중복 부호·지수 표기는 추정하거나 반올림하지 않는다.

숙박 날짜는 실제 입력값/placeholder/명시한 날짜 설정에 맞춰 입력하고 저장 결과를 실제 날짜로 비교한다.
날짜 서식을 확인하지 못하면 입력 전에 보류한다. 목적·코멘트 저장 확인은 CRLF/LF와 NBSP 차이만
정규화하며 원본 사용자 문구나 중간의 여러 공백을 제거하지 않는다.
실행별 ContextVar로 GUI 작업 스레드 및 CLI 설정을 분리하고 실행 뒤 복원한다.

## 범위

경비 목록의 행 탐색·대상별 매칭 정책·달력 UI는 유지한다. 따라서 날짜 해석 실패와
DOM 경비 데이터 행 0건은 별개다. 날짜 순서 차이만으로 기존 0건 오류의 원인을 확정하지 않는다.
새로운 통화 환산, 모든 언어의 버튼/필드명, Excel/CSV 가져오기 서식의 전면 변경은 포함하지 않는다.
확인 불가능한 값은 기존의 대상별 보류·결과 확인 절차로 넘긴다.

## 검증

`tests/test_display_formats.py`에는 실제 거래 대신 합성 데이터로 날짜·금액·통화·부호·공백,
Python/JavaScript 해석 일치, 숙박 입력/재조회, 빈 요금, 스레드 간 설정 격리,
설정창 저장 검사를 추가했다. 관련 회귀 검사만 수행하고 Windows EXE 빌드와 실제 Concur
로그인·첨부·저장·제출은 수행하지 않는다. 정확한 실행 결과는 해당 커밋/CI 기록을 기준으로 한다.
