# 자주 쓰는 추가 참석자 · 체크박스 LOV

## 사용

홈의 `자주 쓰는 추가 참석자 관리` 또는 작업지의 `자주 쓰는 참석자 관리`에서
표시 이름(구분용)과 Concur 검색값(기존에 검색하던 이름/기업 이메일 등)을 등록한다.
`새 항목`, `추가 / 수정`, `선택 삭제`, `목록 저장`을 제공한다.
입력만 하고 목록 저장을 눌러도 마지막 입력을 검사해 포함한다. 같은 검색값의 중복 등록은 차단한다.
검색값이 실제 Concur 계정에 존재하는지 검증하거나 직원을 새로 등록하는 기능은 아니다.

작업지 `추가 참석자` 셀을 더블클릭/Enter로 열거나 행 선택 후 `추가 참석자 선택`을 누른다.
이름/검색값으로 검색하고 체크박스로 여러 명을 고른 뒤 적용한다. 검색 중에도 체크 상태는 유지한다.
`표시 항목 선택/해제`는 검색 결과에만 적용한다. 기존 직접 입력은 미등록/이번 경비만 항목으로 보존한다.
체크 해제 후 적용하면 그 사람은 **작업지의 추가 참석자 칸**에서 빠진다. 취소는 그 칸을 바꾸지 않는다.
F2 또는 문자 타이핑으로 기존 표 직접 입력도 가능하다.

한 건 상세 편집/여러 행 입력에서도 추가 참석자 옆 `선택 ▾`로 동일한 LOV를 연다.
단축키는 F4/Alt+Down이다. 여러 행 입력은 선택한 행의 추가 참석자를 같은 목록으로 바꾸므로
기존 일괄 편집의 덮어쓰기 안내를 확인한다. 표 적용은 한 번의 Undo/Redo로 되돌린다.
상세 편집 안의 LOV는 상세 편집 초안만 바꾸며 `표에 적용` 전에는 작업지를 바꾸지 않는다.

## 보존과 범위

- 기본 참석자 자동 입력과 `참석자` 칸은 변경하지 않는다.
- 즐겨찾기 등록/수정/삭제는 기존 작업지에 소급 적용되지 않는다.
- LOV에서 목록 관리로 즐겨찾기를 저장하는 것과 경비 선택창 적용/취소는 독립이다.
- 빈 추가 참석자는 기존 Concur 값 유지 정책을 따른다. 여기서 Concur 참석자를 삭제하지 않는다.
- 저장 형식은 기존의 쉼표 구분 문자열을 유지한다. 표시 이름 대신 검색값을 기록한다.
- 경비유형별 입력 정책, Concur 검색/매칭/저장 구현은 변경하지 않는다. 설명 전용 유형의 참석자는 계속 미반영이다.
- 즐겨찾기는 프로그램/EXE 옆 `attendee-favorites.json`에 저장한다. 설치 폴더별 목록이며 계정 간 동기화하지 않는다.
  이 파일에 사람 이름과 검색값이 있으므로 공개 공유하지 않는다. Git 무시 목록에 추가했고 배포본에는 실사용 목록을 넣지 않는다.
- 저장 오류/손상된 파일은 빈 목록으로 덮어쓰지 않는다. 중복 편집/동시 저장을 차단하고 임시 파일을 원자적으로 교체한다.

## 검증

Linux Python/Tk/Xvfb/tksheet 7.6.0에서 새 참석자 목록/LOV 테스트와 기존 기본 참석자,
작업지 보존, 빈칸 정책 테스트 총 80개 통과. 검색 후 체크 유지, 미등록 기존값 보존,
등록/수정/삭제/취소, 손상/동시 편집/저장 실패, 필터된 행, 여러 행 입력, 상세 초안,
Undo/Redo와 기본 참석자 보존을 검사했다. Windows EXE 빌드 및 실제 Concur 접속은 수행하지 않았다.
