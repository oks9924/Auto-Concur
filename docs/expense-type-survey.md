# 경비유형 입력 안내 전수조사

## 조사 대상과 색상 의미

`src/settings.py` 기본 목록은 14종이다. 이 목록이 실제 계정의 전체 목록이라는 뜻은 아니다.
먼저 Concur 경비유형 드롭다운을 처음부터 끝까지 확인하고, 누락된 이름도 수집한다.
`개인 식사 (SISW Only)`는 기존 설정에서 의도적으로 제외되어 있다. 이번 조사에서 다시 포함할지는 별도 결정한다.

초록색은 **현재 프로그램의 입력 안내**이지 Concur 필수값이나 저장 성공 표시가 아니다.
기존 3종 규칙도 필수/선택/조건부를 구분해 재확인한다. 미등록 유형은 노란 경비유형 셀과
`안내 미등록` 필터/문구로 드러내며, 이름만 보고 필수값을 추측하지 않는다.
원본 거래일·금액·가맹점은 계속 읽기 전용이다. 이 조사로 자동화 입력 필드가 자동 확대되지는 않는다.

## 화면을 확인할 때

승인된 테스트 리포트/경비를 이용한다. 경비 유형을 변경하면 화면이 재계산되거나 저장될 수 있으므로
실제 제출·승인된 경비를 조사 목적으로 변경하지 않는다. 필요한 탭과 드롭다운을 열어 화면의 필드 이름,
별표, 비활성 여부, 선택지를 확인한다. 저장 오류 검사는 허용된 테스트 경비에서만 한다. 리포트 제출은 하지 않는다.
직원 이름, 카드번호, 거래 금액, 주소, Report ID 등 실제 입력값은 가린다.
단순 화면 캡처는 UI 구현용 selector를 입증하지 못하므로 추가 필드 자동화 연결은 별도 확인한다.

## 유형마다 보낼 양식

```text
경비유형(화면 이름 그대로):
코드(알 때만):
필수 표시 필드(*):
선택 입력 필드:
자동으로 채워지는 필드 / 수정 불가 필드:
조건부 필드(어떤 선택을 하면 생기는지):
드롭다운 이름과 선택지:
별도 탭/참석자/항목별 명세/배부 여부:
현재 프로그램에 없는 필드:
테스트 저장 오류(실제로 확인했을 때만; 미검사면 미검사):
추가 화면 캡처:
```

예: 필드 하나를 `도시 | 드롭다운 | * 표시 있음 | 직접 입력 가능 여부 미확인 | 국내 선택 시 표시`처럼 기록한다.
필수 표시가 없다는 이유만으로 선택 입력이라고 확정하지 않는다. 화면과 검증 메시지가 다르면 둘 다 남긴다.

## 등록 완료 기준

유형 이름/코드 확인 → 필드·선택지·조건 조사 → 사용자 확인 → 입력 안내와 필수 검증 구분 →
프로그램 미지원 필드 처리 결정 → 테스트 경비로 입력/조회 검증. 이 과정을 마친 유형만 완료로 표시한다.
