# 차량 마일리지 전용 표 — 입력/보관 단계

## 이번에 구현한 범위

기존 작업지를 열고 도구 줄의 `차량 마일리지 추가`를 누르면 카드 표 아래에 별도 마일리지 표가 나타난다.
두 표 사이의 구분선을 드래그해 높이를 조절한다. 기존 카드 표의 열과 원본 데이터는 바꾸지 않는다.
현재는 기존 카드 작업지에서 시작한다. 카드 작업지 없이 마일리지만 작성하는 홈 진입은 아직 제공하지 않는다.
마일리지 입력은 별도 폼으로 추가/수정하며 전용 표에서는 목록을 보고 더블클릭/Enter로 수정한다.

입력 필드: 거래 날짜(달력), 출발지, 도착지, 차량 ID(LOV), 거리(km), 탑승자 수, 설명, 지도 이미지.
차량 ID는 `차량 관리`에서 Concur에 본인이 등록한 이름을 정확히 적고 long/short를 지정한다.
이는 로컬 목록이며 Concur의 실제 차량 LOV 자동 조회/계정 유효성 검증은 아직 하지 않는다.
long=470원/km, short=280원/km는 사용자가 제공한 기준이다. 이름으로 용도를 추측하지 않는다.
실제 회사 정책/적용일/Concur 환급률을 확인한 값이라는 뜻이 아니다.

예상금액은 거리×선택 환급률이다. 탑승자 수는 곱하지 않고 별도 보존하며,
거리의 소수는 Decimal로 계산한다. 반올림 정책은 추측하지 않고 실제 Concur 금액으로 확정 표시하지 않는다.
탑승자 수의 운전자 포함 여부는 회사 Concur 입력 기준에 따른다. 0 이상의 정수를 보존한다.
기존 마일리지 행은 당시 차량 이름·구분·환급률을 보존하므로 차량 목록 수정/삭제로 소급 변경되지 않는다.

`지도 이미지 첨부`는 실제 PNG/JPG를 검증해 전표 폴더 안 `mileage-maps/`로 복사한다.
원본 파일을 이동/삭제하지 않는다. 같은 내용은 같은 SHA-256 이름으로 보관한다.
이 하위 폴더는 기존 카드 전표의 최상위 스캔에 섞이지 않는다. 경로와 해시를 저장하고
다시 저장할 때 이미지 존재/변경 여부를 확인한다. 지도·경로·증빙을 생성하거나 조작하지 않는다.
20MB 이하를 지원한다. 개인 주소 등이 있으므로 공개 공유하지 않는다.

`마일리지 표에 적용`은 표 초안을 바꾸고 `마일리지 저장`은 별도 `mileage-workbook.json`에 저장한다.
차량 목록은 프로그램 폴더의 `mileage-vehicles.json`에 저장한다. 프로그램 간/계정 간 자동 동기화하지 않는다.
마일리지 되돌리기/다시 실행은 카드 표의 Ctrl+Z 이력과 분리되어 있다.
표에서 행을 삭제해도 이미지 원본과 보관 파일은 자동 삭제하지 않는다.
창 닫기·카드 반영으로 이동 시 미저장 마일리지 여부를 확인한다.

## 중요한 미구현 범위

**이 커밋은 Concur 자동차 마일리지 신규 경비 생성·차량 LOV 자동 조회·서버 지도 첨부를 실행하지 않는다.**
기존 `Concur 반영`은 카드 경비만 처리한다. 화면과 반영 확인창에 마일리지 제외를 명시한다.
마일리지를 기존 영수증 매칭 대상으로 넣거나 처리 완료로 표시하지 않는다.
추후 신규 경비 생성은 실제 유형 식별·차량 옵션·필드·이미지 업로드·재조회 검증을 연결하고,
저장 도중 중단된 경우 자동 재생성하지 않는 별도 진행 기록을 갖춰야 한다.
기존 카드 실행기는 이미 존재하는 경비 ID를 전제로 하므로 새 경비를 그 경로에 억지로 섞지 않는다.

## 검증

합성 이미지/가상 거래, Tk/Xvfb에서 입력 검증, 금액 계산, 카드 데이터 분리, 지도 복사/변조/누락,
경로 제한, 중복 ID, 동시 저장/저장 실패, 추가/취소/재열기/Undo/Redo, 차량 관리,
기존 추가 참석자 및 기본 참석자와 작업지 검사를 수행한다. Windows EXE 빌드·실계정 실행은 하지 않는다.
