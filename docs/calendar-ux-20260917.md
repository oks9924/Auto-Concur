# 달력 UX 개선과 입력 안내 조사 준비

## 이번 변경

- 공통 CalendarPanel: 연/월 바로 선택, 월 이동, 오늘 표시, 선택/기간 강조.
- 날짜 입력칸: 직접 타이핑과 달력 버튼 병행; F4/Alt+Down/더블클릭으로 달력 열기.
- 날짜 격자: 방향키, Home/End, PageUp/Down, Shift+PageUp/Down, Enter/Space, Esc.
- 조회 기간: 두 날짜를 한 창에서 선택; 오늘/최근 7일/이번 달(오늘까지)/지난달 바로가기.
- 숙박: 화면 공간에 따라 1~2개월 표시, 입실→퇴실 선택, 박수 요약, 1/2/3박 바로가기,
  직접 입력, 선택 초안 취소, 두 날짜 비우기. 적용 전에는 원본을 바꾸지 않는다.
- 조회 기간은 당일 허용, 숙박은 퇴실>입실 검사. 해를 넘기면 연도를 명시한다.
- 작업지 셀/상단 버튼/여러 행 입력의 날짜에도 공통 달력 사용.
- 이전 창의 포커스와 모달 상태 복원. 날짜 격자는 Tab 한 칸으로 접근하고 방향키로 탐색한다.
- 작업지 도구 버튼은 두 줄로 분리. 초기 창 크기를 화면 크기에 맞춰 제한한다.
- 초록색은 기존 3종 입력 안내이며 필수 확정 표시가 아님을 명시한다. 미등록 유형은 노란 셀,
  문구와 필터, 유형 입력 안내 버튼으로 표시한다. 새로운 Concur 업무 규칙은 추정하지 않는다.

## 범위와 한계

Tk 데스크톱 위젯을 개선한 것이며, 웹 프레임워크 전환이나 WCAG 적합성 인증이 아니다.
관련 회귀 검사만 실행한다. Windows EXE 재빌드/실제 Concur 입력 검증은 이번 변경에서 수행하지 않았다.
Concur DOM 탐색·매칭·저장 로직은 변경하지 않았다. 기존 작업지 형식과 원본 보호를 유지한다.
유형 조사 방법과 14종 기본 목록은 [expense-type-survey.md](expense-type-survey.md)에 있다.

## 현재 UI/UX의 남은 개선점 (코드 검토 의견)

전체가 최적화된 상태로 보지는 않는다. 작업지의 입력 상태와 Concur 처리 결과가 분리되어 있고,
넓은 표의 가로 스크롤, 필터와 실제 처리 범위 차이, 진행 로그 중심의 결과 확인,
시작 단계의 선택지와 전문 용어가 여전히 개선 대상이다.
다음 설계 후보: 단계별 진행 표시, 필수/선택/조건부 입력과 기존값 유지 구분, 실행 전 변경 미리보기,
안전한 중단/재개, 실패·보류 결과 표, 작은 화면용 행 상세 편집. 전수조사 결과를 먼저 반영한다.
