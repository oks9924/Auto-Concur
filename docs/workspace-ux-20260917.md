# 작업 공간 UI/UX 개선 (2026-09-17)

## 실제 변경

- 첫 화면을 `전표 준비 → 경비 입력 → Concur 반영 → 결과 확인` 작업 카드로 정리했다.
  기존 작업지는 다운로드/재생성 없이 경비 입력으로 이어갈 수 있다.
- 작업 공간 / 결과 기록 / 상세 로그 탭으로 정보의 목적을 나눴다. 로그 전체 복사를 지원한다.
- 실행/사용자 확인 대기/종료 메시지를 창 상단에 표시한다. 진행률을 임의로 계산하지 않는다.
  실행 중에는 입력 설정을 잠그고 창 닫기를 막아 불명확한 중단을 줄인다.
- 전표 폴더/조회 기간/기본 참석자를 작업 설정에 모았다. 날짜 달력, 표시 서식 설정을 유지한다.
  코드/숙박 선택지 조사 기능은 고급 도구에서 접근한다. 앞 N건에 0·음수·문자를 넣으면
  전체 처리로 바꾸지 않고 입력 오류를 안내한다.
- 작은 첫 화면은 세로 스크롤과 키보드 포커스 따라가기를 지원한다.
- 작업지는 모든 열을 유지한다. `한 건 상세 편집` 또는 Ctrl+E로 선택한 행을 세로 폼에서 편집한다.
  기본/참석자/숙박 그룹, 여러 줄 코멘트, 기존 드롭다운과 공통 달력을 사용한다.
  폼의 `표에 적용`은 작업지에만 적용하며 한 번의 Ctrl+Z로 되돌린다. 취소는 원본을 바꾸지 않는다.
  거래일·금액·가맹점·승인번호·파일 정보는 수정하지 않는다. 저장 시 기존 충돌 검사를 유지한다.
- 자주 쓰는 작업지 버튼은 도구막대에, 나머지는 `더 보기`에 배치한다.
- `저장 후 반영 대상 확인` 전에 표시/전체 행 수와 실제 실행 범위를 안내한다.
  필터와 선택 행은 실행 범위를 제한하지 않는다. 앞 N건은 작업 종류별 제한이며, 영수증만
  처리하는 경우도 있어 실제 건수는 기존 Concur 리포트 확인창에서 결정된다.

## 결과 기록의 의미와 한계

`concur-progress.json`을 읽기 전용으로 보여 준다. `당시 검증됨`, `확인 필요`,
`중단 여부 확인`, `실행 전 확인`을 구분하고 검색/필터/상세 이유/선택 복사를 제공한다.
현재 Concur 값의 실시간 재검증이 아니며, 과거 기록이 이번 실행의 성공을 의미하지 않는다.
리포트 ID와 기록 시각을 함께 보여 주며 서로 다른 입력 내용의 이력은 별도 작업으로 남는다.
매칭 전 보류·취소·목록 탐색 실패는 진행 기록에 없을 수 있어 상세 로그와 함께 확인한다.
읽기 실패 시 이전 표를 비워 오래된 결과가 정상인 것처럼 남지 않게 한다.

## 유지한 경계

경비 읽기·매칭·입력·저장 검증·진행 기록 쓰기·날짜/숫자 서식 해석 코드는 변경하지 않았다.
자동 재전송, Concur 리포트 제출, 전체 유형의 필수값 추정은 추가하지 않았다.
초록색은 기존 확인된 입력 안내이고 미등록 유형 안내를 유지한다.
이번 변경은 Tk 데스크톱 UI 개선이며 웹앱 전환이나 접근성 인증이 아니다.

## 검사

Linux/Tk-Xvfb에서 작업 공간·행 폼·결과 기록·기존 작업지/달력/빈칸 정책 101개 통과.
Concur 표시 서식 설정창 검사 1개도 통과했다. 필터된 행 수정·실행 취소·원본 보존,
날짜 오류·취소·미등록 안내·처리 범위 확인·기록 읽기 오류·실행 중 입력 잠금 등을 검사했다.
변경 전에도 실패하던 달력 회귀 테스트의 예전 year/month 대입은 현행 panel.show API로
수정했으며, 연말~다음 해 범위 선택과 Ctrl+Z 검증은 그대로 유지했다.
Windows EXE 빌드, 실제 Concur 계정 로그인/경비 수정/제출은 수행하지 않았다.

## 적용

Git main 업데이트 후 소스 실행은 run.bat, 단일 EXE는 build_exe.bat으로 새로 빌드한다.
기존 EXE는 자동으로 갱신되지 않는다. 기존 전표·작업지·진행 기록은 삭제할 필요가 없다.
