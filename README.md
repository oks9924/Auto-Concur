# Auto-Concur

현대카드 전표를 정리하고, 프로그램 안에서 경비 정보를 입력한 뒤 Concur에 반영합니다.
**Excel 앱이나 엑셀 파일을 사용하지 않아도 전체 작업을 진행할 수 있습니다.**

## 실행

Windows / Python 3.10 이상을 사용합니다.

1. 소스를 받은 폴더에서 `setup.bat`을 실행합니다. 기존 사용자도 새 표 라이브러리 설치를 위해 한 번 실행합니다.
2. `run.bat`을 실행합니다.
3. 기간과 전표 폴더를 선택합니다.
4. **A. 전표 다운로드** → **B. 파싱 · 작업지 생성** → **작업지 편집** 순서로 진행합니다.
5. 프로그램 표에 내용을 입력하고 **저장하고 Concur 반영**을 누릅니다.

카드 인증과 Concur 로그인·리포트 선택은 직접 합니다. 프로그램의 안내창에서 준비가 끝난 뒤 확인을 누릅니다.

## 프로그램 표

- 전체 열을 항상 표시하고, 경비유형별 입력 안내 칸을 초록색으로 강조합니다.
- 대중교통비는 코멘트(설명)만 반영합니다. 작업지에 기존 비즈니스 목적이 있어도 해당 칸을 찾거나 입력하지 않습니다.
- 제목 표시줄 또는 ‘경비 입력’ 제목을 더블클릭하면 최대화·복원합니다. 글자 크기는 10~14pt로 선택합니다.
- 셀 더블클릭 또는 키 입력으로 편집합니다.
- 셀 범위 선택, Ctrl+C/V 복사·붙여넣기, Ctrl+Z/Y 실행 취소·다시 실행, Delete 비우기를 지원합니다.
- 경비유형·숙박위치·Booking Channel 드롭다운을 제공합니다.
- **여러 행에 입력**으로 선택한 행에 같은 코멘트·참석자·유형 등을 넣을 수 있습니다.
- 검색과 숙박비·식음료·입력 상태 필터를 제공합니다. **필터는 표시만 바꾸며 C단계 처리 대상을 제한하지 않습니다.**
- 거래일·금액·가맹점과 내부 전표 연결 정보는 편집에서 보호합니다.
- 입력 중 임시 저장하며, 같은 원본의 임시본은 다음에 표를 열 때 복원합니다.
- **이전 저장 복원**은 직전 저장의 입력값을 초안으로 되돌립니다. 저장해야 실행 데이터에 반영됩니다.
- 외부에서 원본이 변경되면 덮어쓰기를 중단합니다. **다시 불러오기**로 현재 저장 데이터를 확인할 수 있습니다.
- 필요할 때만 엑셀/CSV/JSON 입력을 가져오거나 엑셀로 내보냅니다. 가져오기는 현재 전표와 승인번호·날짜·금액이 일치하는 입력에 사용합니다.

표의 **입력 있음 / 영수증만 / 입력 확인**은 입력 상태입니다. Concur 반영 성공 여부는 C단계 실행 로그에서 확인합니다.

## 빈칸과 영수증 처리

**빈칸은 Concur의 현재 값을 유지한다는 뜻입니다. 기존 값을 지우라는 뜻이 아닙니다.**

- 유형·목적·코멘트·참석자·숙박 정보는 입력한 필드만 반영합니다.
- 설정에 기본값이 있어도 C단계에서 빈칸을 자동으로 채우지 않습니다.
- 참석자와 추가 참석자가 모두 비면 기존 참석자를 유지합니다. 입력하면 두 칸의 이름을 합쳐 해당 식음료 경비의 참석자를 맞춥니다.
- 입실·퇴실은 둘 다 입력하거나 둘 다 비웁니다. `2026-09-01` 또는 `9/1` 형식을 사용할 수 있습니다.
- 숙박 날짜가 비면 날짜·객실 요금을 바꾸지 않습니다. 숙박위치·Booking Channel만 입력할 수도 있습니다.
- 숙박 날짜를 입력한 경우 기존 로직대로 박수와 경비 금액에 맞춰 객실 요금 입력을 시도합니다. 기존 명세가 있거나 수정 불가인 경우는 자동으로 덮지 않습니다.
- 편집 필드가 전부 비어 있어도 영수증은 화면 상태에 따라 처리합니다. 이미 있으면 건너뛰고 없으면 첨부합니다.
- `attached.txt`는 참고 기록입니다. 이 기록만으로 현재 화면에 영수증이 있다고 판단하지 않습니다.

## 저장 파일

전표 폴더 안에 저장됩니다. 파일을 직접 편집할 필요는 없습니다.

| 파일 | 역할 |
|---|---|
| `workbook.json` | 프로그램 입력 원본, C단계가 우선 읽는 데이터 |
| `workbook.draft.json` | 아직 확정 저장하지 않은 임시 입력 |
| `workbook.previous.json` | 직전 저장의 복원본 |
| `manifest.csv` | B단계가 만든 전표 파일 목록, 첨부에 사용 |
| PDF/사진 | 실제로 첨부할 영수증 |

B단계를 다시 실행해도 저장된 프로그램 입력값을 보존합니다. 파싱 실패가 있으면 기존 입력 데이터를 덮지 않습니다. 기존 XLSX를 읽지 못했을 때 오래된 CSV 값으로 대체하여 덮어쓰던 동작도 중단합니다.

기존 사용자: `workbook.json`이 없으면 기존 `manifest.xlsx` 또는 `manifest.csv`를 열 수 있습니다. 프로그램에서 저장하면 전용 데이터로 전환합니다. 그 후에는 외부 엑셀 변경이 자동으로 반영되지 않으며 **가져오기**를 사용합니다. 계산되지 않은 엑셀 수식은 빈 값으로 읽힐 수 있으므로 가져온 내용을 확인합니다.

## Chromium 화면 안정화

- 브라우저 기본 언어는 한국어(`ko-KR`)입니다. Concur 계정 언어 설정에 따라 영어로 표시될 수 있습니다.
- `Save Expense` 저장 버튼을 지원하고, 경비유형 선택 결과는 실제 옵션 이름으로 확인합니다.
- ‘다른 항목을 업데이트하시겠습니까?’ 확인창에서는 ‘업데이트’를 눌러 현재 경비의 명세에도 변경을 적용합니다.
- 화면 재렌더링 중 버튼이 교체되면 클릭 전에 대상을 다시 찾습니다.
- 현재 보이는 대화상자/패널에서 버튼을 찾고, 숨겨진 입력 템플릿을 제외합니다.
- 저장 버튼이 뒤늦게 나타나거나 다른 요소에 가려진 경우 클릭 준비를 기다립니다.
- 실제 클릭 결과가 불명확하면 저장/추가 버튼을 무조건 다시 누르지 않습니다.
- 숙박비 객실 요금 행들이 나누어 그려져도 예상 행 수와 편집 가능 상태가 준비될 때까지 기다립니다.
- 경비 목록의 일부 행만 준비된 상태에서 매칭을 시작하지 않습니다.
- 화면 탐색 실패 시 `inspect-out/ui-날짜-시간.json`에 해당 단계·버튼·대화상자 정보를 남깁니다.

진단 파일에는 화면의 업무 문구가 포함될 수 있으므로 공유할 때 내용을 확인합니다. 실제 Concur UI 변경이 있는 경우 최신 진단으로 셀렉터와 상태 전환을 검증해야 합니다.

## 명령행

```text
python -m src.gui
python -m src.download_slips --from 2026.09.01 --to 2026.09.30
python -m src.organize ./downloads
python -m src.organize ./downloads --apply
python -m src.update_concur --dir ./downloads
python -m src.update_concur --dir ./downloads --apply --limit 1
```

`organize`의 기본은 파일을 변경하지 않는 미리보기입니다. Concur 명령도 기본은 계획 출력이며 `--apply`가 있어야 반영합니다. GUI의 C단계는 실제로 반영합니다. `--limit`은 각 단계에서 앞 N건씩 제한합니다.

영수증 사진은 `20260901-17000.jpg`처럼 날짜와 금액으로 이름을 지정합니다. 같은 날 같은 금액이면 `20260901-17000-2.jpg`처럼 구분 번호를 붙입니다. HEIC는 지원하지 않습니다.

브라우저는 Playwright Chromium → Edge → Chrome 순서입니다. 기존 `CONCUR_BROWSER` 환경변수로 선택할 수 있습니다. 브라우저만 바꾼다고 화면 전환 문제의 해결이 보장되는 것은 아닙니다.

## 테스트와 배포

```text
python -m pytest -q
```

화면 테스트는 서비스에 로그인하지 않고 Chromium의 합성 HTML에서 실행합니다. 설치된 Chromium 실행 파일은 `AUTO_CONCUR_TEST_BROWSER` 환경변수로 지정할 수 있습니다. 브라우저가 없으면 해당 테스트는 건너뜁니다. GUI 표 테스트에는 Tk가 있는 데스크톱 환경이 필요합니다. 실제 전표 PDF fixture가 없으면 파서 회귀 테스트 6개를 건너뜁니다.

`build_exe.bat`은 PyInstaller 단일 실행파일을 만들고, `make_exe.bat`은 현재 폴더의 venv를 실행하는 작은 C# 런처를 만듭니다. 후자는 폴더 전체가 필요합니다. 두 배포 방식은 별도 빌드 검증이 필요합니다.

코드는 다음 역할로 나뉩니다: `worksheet.py`는 입력 데이터와 저장, `worksheet_editor.py`는 표 UI, `concur_ui.py`는 화면 대기/클릭/진단, 기존 A/B/C 모듈은 다운로드·정리·Concur 반영입니다.
